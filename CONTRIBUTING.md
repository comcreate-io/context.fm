# Contributing

This project is in concept discovery. Start with the [README](README.md) and [implementation plan](docs/PLAN.md).

Use issues to discuss product behavior, API findings, and proposed experiments. Include what was observed, what remains assumed, and a concrete acceptance criterion. Use pull requests for documentation and implementation changes.

Keep changes small and use descriptive branches such as `docs/playback-findings` or `feat/prompt-capture`. Separate verified provider capabilities from proposals. Do not add credentials, personal conversation transcripts, account data, or listening history to commits, issues, or screenshots.

For integrations, describe how the change was verified and what happens when authorization expires, devices disappear, or the listener takes manual control. Tests should cover meaningful behavior and failure modes.

There is no application to run yet. Runtime setup and test commands will be documented when the first implementation is selected.
